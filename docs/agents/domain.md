# Domain docs

Single context. Read these before exploring:

- `CONTEXT.md`: audience, brand, and product decisions. It is Austin's product doc; do not turn it into a glossary.
- `GLOSSARY.md`: domain terms and the spellings to avoid. Use these terms in issue titles, test names, and code.
- `docs/adr/`: decisions that are hard to reverse. If your change contradicts one, say so in the PR and why it is worth reopening.
- `docs/operations/`: intro-call and referral procedures.

Add a term to `GLOSSARY.md` when a new concept gets a name. Offer an ADR only when a decision is hard to reverse, surprising without context, and the result of a real trade-off.
